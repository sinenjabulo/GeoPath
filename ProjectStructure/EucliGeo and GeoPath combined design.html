EucliGeo and GeoPath, combined

One product: EucliGeo's teaching approach (computational thinking, guided diagrams, theorems you can manipulate) running on GeoPath's practice engine (proof builder, mastery tracking, class analytics, performance targets).

The big idea: every problem is solved in four named stages (abstraction, decomposition, pattern recognition, solve), and the app records which stage a learner struggles with, not just whether the answer was right.

Yellow steps are the four thinking stages used in every example.

Abstraction: keep what matters

What am I given? What must I find? Which parts of the diagram do I ignore?

Decomposition: split the diagram

Which smaller diagrams (a triangle, a pair of angles on a chord) can I solve one at a time?

Pattern recognition: match to a theorem

Have I seen this shape before? Which theorem or property fits each part?

Solve: write statements and reasons

What follows from each fact I have? What is the reason for each statement?

Reflect and check

Did I use every given? Does the answer make sense on the diagram? If not, go back to step 1.

Design decisions

Two diagram engines, on purpose. The solver and theorem sliders use the app's own SVG geo-diagram component: small, fast and easy to highlight. GeoGebra is kept for free-form exploration and is loaded through a loader service only when the learner presses "Open in GeoGebra". You can measure the bundle and load-time difference, which is a real performance lesson.

One diagram format. Every example and theorem is a JSON description (points, lines, circles, angles, named highlight keys). The same JSON drives the thumbnail, the solver, the sub-diagrams in decomposition, and the theorem page.

The solver store. solver.store holds the current stage, the learner's choices per stage, the hints and guides used, and per-stage correctness, all as signals. Each stage result is sent to the server as it completes.

Data model changes

TableChange
definitionsNew. term, text, diagram_json, topic_id.
theoremsAdd interactive_config JSONB (sliders, toggles, default values).
questionsRename conceptually to examples. Add stage_config JSONB: the relevant givens and distractors, valid sub-diagrams, and the pattern for each sub-diagram.
attempt_stagesNew. attempt_id, stage (abstraction, decomposition, pattern, solve), is_correct, tries, guides_used, hints_used, duration_ms.
attempt_stepsUnchanged. Still the high-volume proof-step table.
masteryAdd a second kind of row: mastery per thinking stage, not only per theorem.
